# 암기 흐름 검토 및 v0.2.0 변경

기존 프로그램은 매일 카드 한 장을 보여주었지만 회상 성공 여부, 복습 예약, 학습 기록이 없었다. 뜻과 예문이 한 줄에서 잘렸고, 카드가 바뀌어도 정답 공개 상태가 유지될 수 있었다.

이번 변경은 영어 단어 → 뜻 회상 → 답 확인 → 자가 평가 → 기한 복습 흐름을 추가한다. 그림은 HINT로 요청하며 힌트 사용은 회상 실패로 처리한다. 첫 회상 전 답을 보지 않는 습관과, 예문을 소리 내어 읽는 안내를 제공한다. 마이크 채점이나 발음 재생 기능은 포함하지 않는다.

## 코드 검토에서 확인한 오류

- Wi-Fi 연결 여부를 캐시 선택 전에 검사해 오프라인 부팅에서는 인터넷 단어장 캐시를 선택하지 못했다.
- 캐시가 있는 상태에서 첫 동기화가 실패하면 `!everSynced_` 조건 때문에 매 루프 재시도할 수 있었다. 재시도 대기 조건을 먼저 적용한다.
- 자정의 카드 변경 조건이 없어 12시간 동기화 때까지 전날 카드가 남을 수 있었다.
- 다운로드 바이트의 실제 저장 성공 여부와 Content-Length를 검사하지 않아 잘린 파일로 기존 캐시를 교체할 수 있었다.
- 마지막 개행이 없는 여러 줄 파일의 마지막 단어가 집계되지 않았고, 빈 줄이 단어 수에 포함되었다. 모든 읽기 경로에 동일한 제한과 빈 줄 처리를 적용한다.
- 동일한 PNG 설명자 주소를 재사용하므로 그림 변경 시 LVGL 캐시와 위치를 새로 반영한다.
- 매우 짧은 잘못된 PNG의 오류 로그가 버퍼 경계를 넘어 읽을 수 있었다.

## 검증 범위와 제약

호스트 테스트는 실제 복습 정책과 StudyStore 구현을 실행한다. Preferences는 메모리 테스트 대역이다. 펌웨어 컴파일과 호스트 테스트는 화면 터치, 네트워크 실패 주입, NVS 전원 차단 내구성, 실제 스피커 출력을 검증하지 않는다. 실기기 체크리스트는 HARDWARE_TEST.md의 v0.2.0 추가 검증 절에 있다.

스피커의 모델/앰프/연결 핀이 확인되지 않아 오디오 GPIO를 임의로 지정하지 않았다. 다음 단계는 실제 제품 확인 후 발음 버튼과 오디오 파일 공급·캐시 방식을 결정하는 것이다. 한글 폰트는 현재 없으며 한글 뜻 사용 전에 별도 구현해야 한다. 128개 이력 한도 확대도 장기 사용 전 검토 대상이다.

## 최종 검증 기록

- `scripts\test_host.cmd`: 정책·복습 우선순위 및 저장 테스트 모두 통과.
- `scripts\build.ps1 -Environment all`: ILI9341/ST7789 모두 성공, v0.2.0 firmware/merged BIN 생성.
- ILI9341: 정적 RAM 120,872바이트(36.9%), 앱 Flash 1,652,165바이트(84.0%). 런타임 힙 여유는 실측하지 않음.
- 별도 코드 검토에서 발견한 같은 날 동기화 후 내용 미갱신 문제를 보완했다. 현재 단어를 새 manifest에서 철자로 찾아 다시 읽고, 제거된 단어라면 오늘 슬롯으로 돌아간다. 후속 검토에서 중요한 추가 문제는 발견되지 않음.
- 실제 보드 업로드와 실기기 UI 확인은 수행하지 않음. 구현 검증 뒤 사용자가 세션 인계 및 커밋·푸시를 요청했으며, 최신 인계 내용은 HANDOFF.md를 참조.
